# KV 容量读数笔记（kv-memory）

> 记录日期：2026-09-30　实验：`experiments/kv_demo.py`（预注册判据写在该脚本的 docstring 里）
> 目标：验证包内最后一个"候选"函数 `kv_storage_capacity(seq_len, per_token)` ——
> 主张是"KV 记忆的**存储**随条目数线性增长（`seq_len × per_token`），而**单次读出**受被激活内容（流量层）限制"。
> 全部数据来自一个合成联想回忆任务（零新数据，本地生成），93 个微型单元，736 秒。

---

## 1. 设计与预注册

任务：L 个槽位各存一个值（value ∈ 8 类），一次查询指名一个槽位，模型输出该槽位的值。
存储 = `L·ln 8`，单次查询的载荷 = `ln 8`（外加寻址 `ln L`）。

三条臂的**算力完全相同**（编码器与解码器都是两层 MLP，宽度 128）；唯一的差别是 **VQ 瓶颈放在哪里**：

| 臂 | 结构 | 理论需求 |
| --- | --- | --- |
| **KV** | 键走一条未量化的寻址信道；**每个槽位的值**经逐 token VQ(K_tok) 写入；读出 = 对量化载荷做注意力 | 存储 `L·log K_tok`；单次流量 `ln L + ln C_V` |
| **DENSE** | 整张表经**一个** VQ(K_dense)（在查询之前写入）；查询只在解码器处被条件化 | `log K_dense ≥ L·ln C_V`（⇒ `K ≈ C_V^L`） |
| **CTRL** | 查询与表一起喂进编码器，VQ 位于**查询之后** | 只需承载答案 ⇒ `log K ≥ ln C_V = 2.08` |

预注册判据：K1（KV：`K_tok=C_V` 时全部 L ≥0.90，`K_tok=4` 时全部 L ≤0.50）/ K2（DENSE 的最小可用 K 在 `C_V^L` 的 2 倍以内）/ K3（CTRL 在 K=8 时全部 L ≥0.90）/ K4（`L·ln C_V` 在一个八度以内预测稠密墙）。

## 2. 结果

**KV 臂（内容寻址）**

| L | `K_tok=4` (<C_V) | `K_tok=8` (=C_V) | `K_tok=16` (有余量) | 存储 |
| --- | --- | --- | --- | --- |
| 2 | 0.510 | **1.000** | **1.000** | 4.16 nats |
| 4 | 0.484 | **1.000** | **1.000** | 8.32 |
| 8 | 0.518 | **1.000** | **1.000** | 16.6 |
| 16 | 0.490 | 0.877 | **1.000** | 33.3 |

**DENSE 臂**（预测 `C_V^L` = 64 / 512 / 4096）

| L | 最小可用 K（acc≥0.90） | 预测 | 倍数 |
| --- | --- | --- | --- |
| 2 | **96** | 64 | 1.5× |
| 3 | **2048** | 512 | **4.0×** |
| 4 | **>4096**（4096 处仅 0.467） | 4096 | ≥1× |

**CTRL 臂**

| L | K=8 | K=16 | K=64 |
| --- | --- | --- | --- |
| 2 | 0.534 | 0.667 | **1.000** |
| 4 | 0.309 | 0.333 | **0.918** |
| 8 | 0.207 | 0.250 | 0.279 |

## 3. 结论（按预注册，照实）

**Verdict = MIXED/REFUTED**：K1、K2、K3、K4 **全部未中**。

- K1 未中**只因为 L=16 的零余量点**（0.877 vs 阈值 0.90）；同一条臂在 `K_tok=16` 时对全部 L 都是 1.000；
- K2/K4 未中是因为**倍数随 L 增长**（1.5× → 4× → 超出网格）：`L·ln C_V` 把**标度律**说对了，把**常数**说得太低；
- K3 未中：CTRL 臂没有塌缩到 `ln C_V`（K=8 时 0.21–0.53，而 K=64 时在 L=8 又回落到 0.279）。

## 4. 数据实际上说明了什么（机制读法）

1. **存储层：成立（这正是本函数的核心主张）**。`K_tok` 固定在 8/16，L 从 2 增到 16（存储 4.16 → 33.3 nats，**8×**）而精度保持 1.000 —— **记忆所服务的信息总量随条目数线性增长，与逐 token 码本大小无关**。
2. **流量层：成立（逐 token 才是约束）**。`K_tok=4 < C_V` 时 4 个 L 的精度全部**锁死在 0.48–0.52**（≈4/8 = 可表征值类的比例），**加槽位完全无用** —— 这正是"单次读出受被激活内容限制"的直接证据。
3. **稠密对照：标度律成立，常数过于乐观**。需求确实随 L 指数增长（96 → 2048 → >4096），方向与 `L·ln C_V` 一致；但实测常数比公式高 1.5–4×，且**倍数随 L 上升** —— 该公式是一个**乐观地板**，不是可达目标。
4. **瓶颈位置的对照臂失败，而失败的方式很有信息量**：把 VQ 移到查询之后**并没有**把需求压到 `ln C_V`。原因是 **VQ 的可用容量 ≠ 其标称容量**：在"零余量"区制下，量化器要学的是"把共享同一答案的输入聚成一类"这个**划分任务**，它比信息需求难得多（K=8 时 0.2–0.5；K=64 时在 L=8 回落到 0.279）。这与项目在别处反复测到的现象同源：`H(Z)` 填不满 `log K`、KD 的长尾衰减，以及**下界相对实测墙的松弛**（`bound-looseness.md`：38/38 个场景 `K_wall > K_min`）。

## 5. 对包本身的处置（已实现）

`kv_storage_capacity` 的状态从"**候选、未验证**"改为**部分验证**，并把实测边界写进了 docstring：

- **存储层已验证**（联想回忆，L 2→16，存储增长 8×，逐 token 码本不变）；
- **流量层机制已验证**（逐 token 容量低于载荷熵时，加槽位无用）；
- **公式的常数乐观了 1.5–4×，且倍数随 L 上升** ⇒ 该函数只能当设计用的**乐观地板**，不能当可达目标；
- 4 条预注册严格判据**全部未中**，照实记录（失败原因是零余量阈值与倍数设定，不是机制不存在）。

README 的接线表也相应从"候选/未验证"改为"**部分验证（存储层 + 流量层机制）；常数乐观 1.5–4×**"。

## 6. 边界

- 合成联想回忆任务（L ≤ 16，8 个值类，4096 条序列，3 个种子）；值与键都是离散 one-hot，**不覆盖连续/自然语言记忆**；
- 注意力寻址信道**未量化**（与 MOE 的 oracle 路由同样处理：路由/寻址信息计入流量层，但不被载荷码本承载）；
- CTRL 臂的失败**不能**用来推断"瓶颈位置无所谓"（信息上它确实只需要 `ln C_V`）；它说明的是**在零余量区制下 VQ 学不会那个划分** —— 这是量化器的可学性限制，不是信息论限制；
- 若将来要重跑一个更干净的版本，预注册应当写明：① 把零余量点（`K_tok=C_V`）单列并声明其预期（≈0.9 而不是恒定 1.0）；② 标度律判据改用"倍数随 L 单调不减"代替固定的 2 倍。
