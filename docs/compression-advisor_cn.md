# 压缩预算顾问

> **模块**：`capacity_lens.compress` ｜ **命令行**：`python -m capacity_lens.compress --acc 0.918`

它是**顾问**，不是压缩器：从不训练被压缩的模型，也从不主张性能提升。它只回答关于**你已经训练好的模型**的三个问题——*我的预算到底可不可行*、*该花在哪一层*、*能期待掉多少*——并且给每个答案标注**证据强度**。

## 证据分级

| 分级 | 含义 | 例子 |
| --- | --- | --- |
| **【可证】** | 由定理保证（Fano 不等式、容量记账） | 地板 `R_IB`、`K_min`、否决门、松紧区间 |
| **【实测】** | 在当前实例上直接测量，且对**被预测的对象零训练** | 整网分配、硬分区保留率 |
| **【归档】** | 此前在实验活动中测得的常数，连同任务与协议一起引用 | 地板与拐点之比 10–30×、保留率 0.15–0.75 |
| **【估计·松】** | 有已知松紧倍数的估计 | 分区天花板，松 2–3× |

## 可证量

- `task_info_floor(acc, n_classes, h_y)` —— `R_IB`，即 C 类任务在该错误率下**可证需要**的信息量。**类别不均衡时必须传经验 `H(y)`**：默认的 `ln C` 会高估地板、从而低估松紧（`balance_warning` 会报出差值）。
- `capacity_floors(rib)` —— 码本大小、以 nats 计的容量、以及每维比特下界。在低信息任务上（MNIST 只有 `ln 10` nats）比特下界**退化为 1 个 level**；这是界本身的性质，不是缺陷。
- `veto(k_codes, capacity_nats, rib)` —— 当压缩后的信息通路低于地板时给出 **IMPOSSIBLE**。它是**可靠的**，但**只是必要条件**：实测地板比实用拐点低 **10–30×**，所以这道门只在极端过压时触发。
- `tightness_interval(i_lb, rib, h_y)` —— 把真实的任务相关松紧夹在 `i_lb / R_IB`（Fano）与 `H(y) / R_IB`（平凡上界）之间。已登记实例：MNIST **≤1.253×**、CIFAR-10 **≤1.917×**。

## 实测量（零训练）

- `partition_retention(z_fit, y_fit, z_eval, y_eval, k, n_classes)` —— 硬量化到 K 个码之后，`I(z;y)` 还剩多少。码本在一个划分上拟合、在**不相交**的另一个划分上测量，且必须满足 `len(z_eval) ≥ 4·K·C`，否则插值互信息会塌向零。已登记：**0.65**（MNIST 末层）、**0.59**（CIFAR-10 卷积主干）、**0.15–0.25**（一个较难的合成 MLP）——即 **0.15–0.75，且始终低于 1**。保留率同时取决于**任务**与**被划分的表征**，所以报告必须写明表征。
- `partition_ceiling(i_code, n_classes, h_y)` —— 任何"只看得到携带 `i_code` nats 的码"的解码器的精度天花板。方向可靠，但**松 2–3×**：当否决线用，不当预测用。

## 本模块拒绝掩盖的边界

1. **绝不能让逐层代理把某层压到下限。** 秩饥饿**不可逆**（实测：保留率 −0.205，6 个种子中 0 个能被微调救回）。相比之下位宽饥饿可被 QAT 找回，这正是允许混合精度、且它在紧位宽处收益最大的原因。
2. **只能用验证集上的整网评估来分配** —— 不能靠逐层曲线求和，也不能在测试集上搜索。
3. **每一堵墙都是协议相对的**（学习率与调度在记录中能让它移动至少 8×）：引用数值时必须带上指纹。
4. **工具的这些读数支撑的是守卫与诊断；它们不会让模型变好。**

## 命令行

```bash
python -m capacity_lens.compress --acc 0.918 --classes 10 --h-y 2.3005 --i-lb 1.97 --k-codes 64
python -m capacity_lens.compress --selftest
```

命令行只打印**可证**部分（不需要模型与数据）。**实测**部分需要训练好的模型，因此留在实验侧的驱动脚本里。
